# R2D2 StabX Web Proxy

Плагин открывает веб-интерфейс StabX `http://pizero2:8080/` через Raspberry Pi
R2D2. Он предназначен для ситуации, когда Pi Zero подключена к точке доступа
`uapilot` или `uapilotstab`, но компьютер оператора не имеет прямого маршрута к
ней.

```text
Компьютер оператора
  http://10.70.175.1:18080 (пример адреса шлюза R2D2)
             |
             v
Raspberry Pi R2D2 + контейнер koropwnz/stab-r2d2-plugin
             |
             v
       pizero2:8080 (StabX web)
       pizero2:5050 (StabX second service)
```

Проксируются обычные HTTP-запросы, POST-запросы настроек, потоковые ответы и
WebSocket. Абсолютные ссылки на `pizero2:8080` переписываются на адрес прокси.

## Файлы

- `plugin/plugin.py` - код бортового прокси.
- `plugin/Dockerfile` - мультиархитектурный контейнер.
- `plugin/build.sh` - сборка и публикация arm64+amd64.
- `plugin/publish.ps1` - та же публикация из Windows PowerShell.
- `plugin/build-local.ps1` - локальная сборка для проверки.
- `plugin/export-arm64.ps1` - экспорт arm64-образа в TAR для ручной загрузки.
- `catalog-entry.json` - готовый файл для окна «Імпорт плагіна з JSON-файлу»:
  метаданные, версия, схема формы и настройки по умолчанию.
- `plugin-config.local.json` - запись для ручного добавления в конфигурацию борта.
- `desktop/open-stabh.bat` - двойной клик: найти шлюз точки доступа и открыть StabX.
- `tests/test_proxy.py` - интеграционные проверки HTTP, POST, WebSocket и авторизации.

## Настройки по умолчанию

```json
{
  "TARGET_HOSTS": "pizero2,pizero2.local",
  "TARGET_PORT": 8080,
  "LISTEN_PORT": 18080,
  "SECONDARY_TARGET_PORT": 5050,
  "SECONDARY_LISTEN_PORT": 15050,
  "REMOTE_TUNNEL_ENABLED": true,
  "REMOTE_MAX_RESPONSE_BYTES": 4194304,
  "PROXY_USERNAME": "",
  "PROXY_PASSWORD": "",
  "CONNECT_TIMEOUT": 5.0,
  "REWRITE_ABSOLUTE_URLS": true
}
```

Если R2D2 не разрешает имена `pizero2` и `pizero2.local`, включённый по умолчанию
`AUTO_DISCOVER` ищет StabX в DHCP/ARP и локальных сетях `/24`. Повторный поиск
выполняется каждые `DISCOVERY_INTERVAL` секунд (по умолчанию 60). Фактический IP
также можно записать в `TARGET_HOSTS`; несколько адресов проверяются слева направо.
В логе версии 0.1.3 выводятся сети R2D2 и DHCP/ARP-соседи, поэтому видно, получил
ли StabX адрес по Wi-Fi и на каком из портов 8080/5050 найден сервис.

## Сборка и публикация в Docker Hub

1. Войдите в Docker Hub командой `docker login` под пользователем `koropwnz`.
2. На компьютере с Docker откройте PowerShell в папке `plugin`.
3. Выполните `./publish.ps1`. Скрипт соберёт и опубликует
   `koropwnz/stab-r2d2-plugin:0.1.2` для `linux/arm64` и `linux/amd64`.
   Эквивалент для Git Bash или WSL: `bash build.sh`.
4. Команда `docker push koropwnz/stab-r2d2-plugin:0.1.2` подходит только тогда,
   когда мультиархитектурный образ уже собран и помечен этим тегом.
5. В веб-админке откройте «Мои плагины» и создайте запись из
   `catalog-entry.json`.
6. В форме укажите registry `registry-1.docker.io`, а в поле «Ключ» укажите
   `koropwnz/stab-r2d2-plugin`. Предпросмотр должен показать
   `registry-1.docker.io/koropwnz/stab-r2d2-plugin:0.1.2`.
7. Скопируйте ID записи.
8. На наземной станции откройте «Плагины» -> «Добавить мой плагин», вставьте ID,
   включите плагин и сохраните настройки.
9. В «Статусах плагинов» дождитесь зелёного состояния `running`.

Для ручной установки образа запустите `plugin/export-arm64.ps1`. Полученный TAR
имеет правильный внутренний тег
`koropwnz/stab-r2d2-plugin:0.1.2`; загружать его на борт нужно по
процедуре «Способ В» из инструкции R2D2.

## Подключение

### Через Интернет-соединение R2D2

1. Запустите наземное приложение R2D2 и дождитесь подключения к нужному борту.
2. Убедитесь, что плагин имеет состояние `running`.
3. Дважды нажмите `desktop/open-stabh-internet.bat` и оставьте консоль открытой.
4. После обнаружения бортового плагина автоматически откроются:
   `http://127.0.0.1:18080/` для StabX `pizero2:8080` и
   `http://127.0.0.1:15050/` для StabX `pizero2:5050`.
5. Локальный мост использует WebSocket наземной станции
   `ws://127.0.0.1:54546/`; внешний IP и проброс портов не нужны.

Интернет-мост предназначен для страниц конфигурации и команд управления.
Видео и MJPEG через служебный канал R2D2 намеренно блокируются, чтобы не
забивать канал управления. Не используйте интернет-мост во время полёта.

### Через локальную точку доступа

1. Подключите компьютер к `uapilot` или `uapilotstab`, либо используйте уже
   настроенный маршрутизируемый адрес R2D2.
2. Дважды нажмите `desktop/open-stabh.bat`. Скрипт проверит активные IPv4-шлюзы
   и откроет найденный адрес на порту `18080`.
3. Скрипт сам сформирует конкретный адрес, например
   `http://10.70.175.1:18080/`, если шлюз R2D2 имеет адрес `10.70.175.1`.
4. Сервис StabX на исходном порту `5050` доступен через тот же адрес R2D2,
   но на порту `15050`, например `http://10.70.175.1:15050/`.
5. Для диагностики добавьте к нужному адресу путь
   `/__r2_stabh_proxy/status`.

Если контейнер имеет статус `running`, но порты `18080` и `15050` недоступны с удалённого
рабочего места, сетевой шлюз R2D2 не маршрутизирует произвольные TCP-порты. В
таком случае команде R2D2 нужно разрешить/пробросить TCP 18080. Канал
`R2Telemetry` предназначен для небольшого JSON примерно раз в секунду и не
подходит для полноценного веб-интерфейса.

## Безопасность

При доступе не только через изолированную точку доступа задайте
`PROXY_USERNAME` и `PROXY_PASSWORD`. Плагин включит HTTP Basic Authentication и
не передаст эти данные дальше в StabX. Собственная авторизация StabX продолжает
работать независимо.

## Логи

Нормальный запуск выглядит так:

```text
INFO: StabX proxy listening on 0.0.0.0:18080 for pizero2,pizero2.local:8080
INFO: StabX proxy listening on 0.0.0.0:15050 for pizero2,pizero2.local:5050
INFO: StabX online at 10.70.175.40:8080
INFO: StabX online at 10.70.175.40:5050
```

Если StabX выключена или не подключилась к точке доступа, контейнер не падает:

```text
WARNING: StabX unavailable; proxy remains ready
```
